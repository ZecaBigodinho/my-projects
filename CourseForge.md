## 🚀 Project Overview

**CourseForge** is an educational technology project designed to organize technical learning material using principles commonly associated with software development and technical documentation.

Instead of treating course content as a collection of isolated documents, PDFs and presentation files, CourseForge organizes educational material as a structured and version-controlled project.

The platform has been used to support programming education by combining:

* Structured lessons
* Technical explanations
* Code examples
* Practical exercises
* Student projects
* Supplementary material
* Git-based version control
* Web-accessible documentation

The central idea is simple:

```text
Educational Content
        ↓
Structured Markdown
        ↓
Version Control
        ↓
MkDocs
        ↓
Web Learning Environment
```

This allows educational material to evolve similarly to a software project.

---

## 🎯 Problem

Technical course material is frequently distributed across multiple formats and locations.

A course may contain:

```text
PDF files
Word documents
Slides
Code examples
Exercise sheets
Links
Images
Loose notes
```

As the amount of content grows, maintaining consistency becomes increasingly difficult.

Changes may need to be repeated across multiple documents, outdated versions may remain available, and students may have difficulty identifying the correct learning sequence.

CourseForge explores a different approach:

```text
Content as Documents
        ↓
Content as Structured Source
```

Instead of maintaining only final documents, the educational content itself becomes part of a structured repository.

---

## 💡 Core Idea

CourseForge treats educational material as something that can be:

* Structured
* Versioned
* Reviewed
* Updated
* Reorganized
* Automated
* Published

This creates similarities between course development and software development.

```text
Software Development
        │
        ├── Source files
        ├── Version control
        ├── Documentation
        ├── Reviews
        └── Releases

Educational Content
        │
        ├── Markdown files
        ├── Version control
        ├── Lessons
        ├── Reviews
        └── Published course
```

The objective is not to turn teaching into software development, but to reuse engineering practices that make complex information easier to maintain.

## 📝 Markdown-Based Content

The primary content format used by CourseForge is **Markdown**.

Markdown allows lessons to remain readable as plain text while supporting:

* Headings
* Lists
* Code blocks
* Tables
* Links
* Images
* Technical examples

A simplified lesson structure may look like:

```text
Lesson
  │
  ├── Introduction
  ├── Concepts
  ├── Examples
  ├── Code
  ├── Exercises
  └── Project Task
```

Because the source content remains lightweight, it can be edited with standard development tools.

## 🌐 MkDocs

CourseForge uses **MkDocs** to transform Markdown files into a navigable static website.

The basic publication workflow is:

```text

    ↓

    ↓

Browser
```

This provides students with a structured interface for navigating educational material.

## 🔗 Integration with EPP

CourseForge is conceptually connected to the **Exercise Processing Pipeline (EPP)**.

The two projects have different responsibilities.

### EPP

Responsible for processing educational exercises.

```text
External Exercise Sources
          ↓
Processing
          ↓
Validation
          ↓
Structured Exercises
```

### CourseForge

Responsible for organizing and presenting educational content.

```text
Structured Content
        ↓
Course Organization
        ↓
MkDocs
        ↓
Learning Environment
```

Together, the broader workflow becomes:

```text
External Sources
       ↓
      EPP
       ↓
Validated Educational Content
       ↓
  CourseForge
       ↓
Structured Learning Environment
       ↓
    Students
```

This separation prevents CourseForge from becoming responsible for web extraction and low-level exercise processing.

---

## 🧩 Separation of Responsibilities

The relationship between the systems can be summarized as:

| System          | Primary Responsibility                              |
| --------------- | --------------------------------------------------- |
| **EPP**         | Acquire, process and validate educational exercises |
| **CourseForge** | Organize and present educational material           |
| **MkDocs**      | Generate the static learning website                |
| **Git/GitHub**  | Version and manage source content                   |
| **AI Tools**    | Assist selected content-development workflows       |

This keeps individual components focused on specific responsibilities.

## 🚧 Main Challenges

### 1. Maintaining Content Consistency

As a course grows, maintaining consistent structure across lessons becomes increasingly difficult.

Using standardized Markdown structures helps reduce this problem.

---

### 2. Balancing Classroom and Documentation

Educational documentation should support the teacher rather than duplicate every classroom interaction.

CourseForge therefore focuses on providing persistent technical reference material while allowing classroom instruction to remain flexible.

---

### 3. Avoiding Excessive Fragmentation

A course can become difficult to navigate if every small topic becomes an independent chapter.

Part of the design process involves deciding when multiple related topics should be grouped into larger learning units.

---

### 4. AI Content Reliability

AI can accelerate content creation, but generated material may contain:

* Incorrect explanations
* Inconsistent formatting
* Unnecessary sections
* Invalid code
* Content that does not match the course

Human review remains necessary.

---

### 5. Keeping Source and Presentation Separate

Course content should remain maintainable independently of the final visual presentation.

Using Markdown as source and MkDocs as the rendering layer helps maintain this separation.

## 📚 Key Learnings

One of the main lessons from CourseForge is that educational content benefits from many of the same practices used in software engineering.

Large courses become easier to maintain when content has:

```text

Standards
    +
Reusable Patterns
    +
Review
```

Another important lesson is that documentation can become part of the learning experience itself.

Students are not limited to receiving information during classroom hours.

A structured technical website provides a persistent reference that can be revisited during exercises and project development.
